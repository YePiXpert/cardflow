# 60 · 安全与隐私方案：威胁模型、控制、密钥、备份、删除、合规待核查

版本 0.1 · 2026-10-16。参考 OWASP MASVS v2.1.0（S11，八个控制组；OWASP 不提供认证，本项目不声称认证）与后端 ASVS。合规依据 S05/S06/S12/S13。

## 1. 数据分级

| 类别 | 示例 | 级别 | 存储/加密 | 允许进入日志/埋点/崩溃报告/通知 |
|---|---|---|---|---|
| 金融账户标识 | 银行、末四位、账户别名 | 敏感（PIPL 第二十八条"金融账户"） | 本地加密库；服务端 RLS | 否（通知只用别名+末四位可配置） |
| 账单正文与交易 | 金额、商户、日期 | 敏感 | 同上 | 否 |
| 原始附件 | PDF/截图（可能含完整卡号） | 高敏 | 本地 AES-GCM；服务端信封加密 | 否；不进 AI 请求 |
| 现金余额与收入 | 快照、收入计划 | 敏感 | 同上 | 否 |
| 凭证 | 令牌、密钥、PDF 密码 | 机密 | Keychain/Keystore；服务端 secret 文件；PDF 密码仅内存 | 绝不 |
| 配置与偏好 | 主题、提醒天数 | 普通 | 明文 | 可 |

禁止项：完整卡号、CVV、PIN、短信验证码、网银密码不设输入字段；任何字段检测到 ≥13 位连续数字拒绝保存（R-CARD-02）。

## 2. 威胁模型（摘要）

| 威胁 | 资产 | 途径 | 控制 | 测试 |
|---|---|---|---|---|
| 设备丢失/被盗 | 本地数据 | 物理访问 | 加密 SQLite + 系统锁 + 应用锁（生物识别）+ 锁屏隐藏金额 | TC-SEC-M01 |
| 备份文件泄露 | 备份 | 云盘/传输 | 口令派生密钥（Argon2id）AES-GCM；无口令不可读 | TC-SEC-M05 |
| 恶意导入文件 | 解析器/设备 | PDF/JS/zip 炸弹/路径穿越 | 类型嗅探、大小/超时、禁用 JS/外链、隔离解析、不递归解压 | F-47 |
| 跨用户数据串联 | 服务端数据 | API 参数篡改/SQL | RLS + 复合外键 + 服务端授权 + 绕过测试 | TC-DB-05 |
| 令牌泄露 | 会话 | 中间人/日志 | TLS、短期令牌、刷新轮换、撤销、日志脱敏 | TC-SEC-S02 |
| 同步重放/伪造 | 数据完整性 | 重放请求 | 幂等键唯一、行版本、设备签名（可选） | TC-SYNC-03 |
| SSRF/内网探测 | 服务器 | 活动链接抓取 | 域名白名单、禁止私网地址、禁跟随到内网、超时 | TC-SEC-S06 |
| 提示注入 | AI 适配器 | 文档内嵌指令 | 内容作数据、输出 schema 校验、无工具调用、不送原始文档 | TC-SEC-S08 |
| 后台越权 | 账单正文 | operator 账号 | RBAC + 数据库角色不授予正文列 + 审计 | TC-SEC-S04 |
| 密钥丢失 | 附件/备份 | KEK/口令丢失 | 明确后果与恢复路径（§5） | 演练 |
| 供应链 | 依赖 | 恶意包 | 锁文件、校验和、最小依赖、定期审计 | CI |

## 3. 移动端控制（MASVS 分组）

| 组 | 控制 | 检查 ID |
|---|---|---|
| STORAGE | 数据库加密（sqlite3mc/SQLCipher），密钥在 Keychain（WhenUnlockedThisDeviceOnly）/Keystore；附件 AES-GCM 每文件密钥；不写外部存储；剪贴板不自动放金额；截图/最近任务预览可选遮罩 | SEC-M-01~05 |
| CRYPTO | 仅平台/标准库算法；随机数来自系统；密钥派生 Argon2id（备份）；无自实现算法 | SEC-M-06~08 |
| AUTH | 应用锁：系统生物识别/设备密码（local_auth），超时可配；不自行采集生物信息；服务端令牌短期 + 轮换 | SEC-M-09~11 |
| NETWORK | 仅 TLS 1.2+；证书校验不可关闭；可选证书固定（自托管用户自配）；无明文回退 | SEC-M-12~13 |
| PLATFORM | 深链校验；分享接收文件沙箱；无短信权限（iOS）；Android 可选 flavor 才有 SMS 权限；WebView 禁用（活动页用外部浏览器） | SEC-M-14~17 |
| CODE | 依赖锁定与审计；Release 混淆（Dart obfuscate）；调试日志在 Release 关闭；崩溃报告（若启用）不含业务内容 | SEC-M-18~20 |
| RESILIENCE | 越狱/root 检测仅提示不阻断；篡改检测（签名校验）：用户自签（ADR-015），期望证书指纹在构建时由用户注入，未配置则跳过，只提示不阻断；不存放服务端密钥 | SEC-M-21~22 |
| PRIVACY | 隐私授权中心逐项开关；最小权限；本地优先默认；Apple 隐私清单（PrivacyInfo.xcprivacy）与实际一致；Play 数据安全表仅上架时需要（v1 不上架，ADR-015） | SEC-M-23~25 |

## 4. 服务端控制（ASVS 对齐）

| 领域 | 控制 | 检查 ID |
|---|---|---|
| 最小权限 | 容器非 root；DB 业务角色无 BYPASSRLS；admin 角色不含正文列 | SEC-S-01 |
| 传输 | TLS 终止在用户反代；容器仅 127.0.0.1；HSTS 由反代配置 | SEC-S-02 |
| 会话 | PyJWT 短期（15 min）+ 刷新轮换 + 服务端撤销表；设备撤销级联 | SEC-S-03 |
| 授权 | 每请求校验工作空间成员资格；RLS 二道防线；后台 RBAC | SEC-S-04 |
| 输入 | pydantic 严格模式；文件类型嗅探；大小/超时；HTML 净化 | SEC-S-05 |
| SSRF | 白名单域 + 私网拒绝 + 重定向校验 | SEC-S-06 |
| 秘密 | KEK/JWT 密钥/DB 口令在 secret 文件（Compose secrets），不进镜像/Git/日志 | SEC-S-07 |
| 日志 | 结构化 JSON；字段白名单；request_id；不含金额/商户/附件内容 | SEC-S-08 |
| 审计 | 后台与敏感用户操作写 audit_log（哈希不存正文） | SEC-S-09 |
| 备份 | 加密、校验、异地可选、恢复演练 | SEC-S-10 |
| 依赖 | 锁文件、`pip-audit`/`npm audit` 在 CI | SEC-S-11 |

### 4.1 数据库角色与行级安全（M0 迁移 0003 已实现）

完整设计、授权矩阵与策略清单见 `evidence/m0/T-006/rls-design.md`；覆盖情况见 `evidence/m0/T-006/rls-coverage.md`。

**组角色**：均为 NOLOGIN，无 BYPASSRLS，非超级用户，也不是表属主。

| 组角色 | 用途 |
|---|---|
| `cardflow_app` | API |
| `cardflow_worker` | 后台任务。可跨空间访问 jobs 与 worker_heartbeats，业务表按任务绑定的空间受限；对身份类表只读，对会话表与幂等表无权限 |
| `cardflow_admin` | 只读元数据视图、维护模板、只读审计；对正文表与正文列无权限 |
| `cardflow_purge` | 物理清除。worker 登录角色以 `WITH INHERIT FALSE, SET TRUE` 获得，清除时必须显式 `SET LOCAL ROLE`，并持有事务级清除令牌 |
| `cardflow_admin_views` | 后台视图属主。用专用 `USING (true)` 策略加列级授权，不需要 BYPASSRLS |

**登录角色**：由 `cardflow db-provision` 幂等创建 `cardflow_api`、`cardflow_worker_login`、`cardflow_admin_login`，口令来自 secret 文件。

**策略与授权**：
- 57 张表启用 ENABLE + FORCE RLS（所有带 workspace_id 的表，加上 workspaces、users）。
- 策略统一比较 `NULLIF(current_setting('app.workspace_id', true), '')::uuid`；未绑定空间时读不到任何租户行。
- 模板行（workspace_id IS NULL）对业务角色只读，只有后台可写。
- 列级 UPDATE 只开放正向列出的列。受保护事实表只能做一次 tombstone，不授 DELETE/TRUNCATE。审计只追加。

**数据库级加固**：
- 对 PUBLIC 收回 TEMPORARY（防临时表遮蔽，R2-01）。
- 对 PUBLIC 收回自有函数的 EXECUTE。
- 触发器函数固定 search_path。

**威胁模型**：
- `app.workspace_id` 是任何会话都能自行设置的参数，所以 RLS 只防应用逻辑错误，防不了 SQL 注入。
- 注入场景下，依靠复合外键、作用域与不可变触发器、列级授权兜底。
- 应用代码一律参数化查询，并通过 `workspace_tx` 绑定空间。

**部署前提**：
- 迁移与 db-provision 以超级用户运行。
- api、worker、后台分别使用各自的登录角色。
- 后台视图的"样本 <5 显示 <5"在 API 层实现。

## 5. 密钥管理

| 密钥 | 生成 | 存放 | 轮换 | 丢失后果 |
|---|---|---|---|---|
| 设备数据库密钥 | 首次启动随机 256 位 | Keychain/Keystore | 换设备时不迁移（新设备新密钥，数据经备份/同步恢复）；更换签名身份视同换设备（ADR-015） | 本地数据不可读；从备份/服务器恢复 |
| 附件文件密钥 | 每文件随机 | 包裹后存库 | 随文件 | 该文件不可读 |
| 备份密钥 | 用户口令 Argon2id | 不存储 | 每次备份可换口令 | 该备份不可恢复（明确告知） |
| 服务端 KEK | 部署时生成 | secret 文件（0600） | 年度或泄露时：解包→重包 DEK | 所有服务端附件不可读（业务数据仍可读） |
| 工作空间 DEK | 创建空间时 | 库内（KEK 包裹） | 随 KEK | 同上 |
| JWT 签名密钥 | 部署时 | secret 文件 | 轮换时并存双密钥 7 天 | 全部会话失效 |

## 6. 备份与恢复

- 设备端备份：`cardflow-backup-<date>.cfb` = zip(manifest.json{schema_version, created_at, counts, sha256 列表}, db.json 导出或加密 DB 副本, attachments/)，整体 AES-256-GCM（Argon2id 口令派生）；恢复时校验 manifest 与每文件 sha256，版本高于当前应用→提示升级。
- 服务端备份：每日 `pg_dump -Fc` + 附件目录 tar + manifest；用 KEK 派生密钥加密；保留 14 日 / 8 周；恢复演练季度一次（隔离 Compose 项目）；RPO 24 h、RTO 1 h（目标值）。
- 新设备恢复流程 UF-9；完整性核验失败阻止导入。

## 8. AI 数据外送（ADR-013）

流程：用户在隐私中心开启 → 每次使用前显示接收方、地区、用途、数据类型（仅脱敏抽取字段/条款文本）、保留期 → 明确同意 → 记录 consent。默认不送原始账单。App Review 5.1.2(i) 要求的"清楚披露 + 明确许可"在此实现。境外服务商 → 列出跨境处理要求（PIPL 第三十八、三十九条）由用户自行评估。

## 9. 非可信输入

导入文件、活动网页、邮件正文、AI 输出均为非可信：HTML 净化、禁用跟踪加载、文件类型/大小/时限限制、路径穿越防护、URL 白名单与 SSRF 防护；文档中出现的"指令"不得影响开发代理或运行时 AI 的工具调用与数据外传。
