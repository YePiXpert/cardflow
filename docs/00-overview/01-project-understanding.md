# 01 · 项目理解、关键假设、资料核验与旧原型差距

核验日期：2026-10-16（Asia/Shanghai）。本文回答"我们到底在做什么、环境允许什么、哪些事实已核验、哪些只是假设"。

## 1. 任务理解

**一句话问题**：持有多张信用卡、已有账单和未来现金流的个人，在录入一笔计划消费后，得到"用哪张卡、各多少钱、何时出账、何时还款、哪个现金账户承担、哪些活动权益确实适用"的可复现、可解释答案，并能把整个账单—还款—现金—活动—权益闭环长期维护下去。

**交付形态**：Flutter iOS（主）+ Android（完整，不做空壳）原生 App；响应式 Web 管理后台；可选自托管 FastAPI + PostgreSQL 后端（Docker Compose，Linux VPS）。Web/PWA 只是补充，不替代原生安装交付。

**本轮边界**：完整产品规划 + 关键技术核验 + 实施任务拆解。已做的编码只有一个用于核验语义的参考引擎 PoC（`poc/engine_reference/`），它是 golden-fixture 预言机，不是生产代码，不进入 App 工程。

**不做的事**：不发起支付/自动还款/借款/调额/改账单日；不做社交、商城、征信评分、贷款导流；不设计虚构交易、商户伪装或规避风控；不声称已实时同步任何银行。

## 3. 旧原型核验与差距（附录 B → 正式方案）

本轮未取得原型文件，无法复算其代码；以下按附录 B 所述缺陷逐条给出正式方案的处理，并在 PoC 中实证了对应语义。

| # | 附录 B 发现 | 正式方案处理 | 落点 |
|---|---|---|---|
| 1 | 500 元步长三卡穷举 | CP-SAT 整数分精确求解 + 独立验证器；状态 OPTIMAL/FEASIBLE/INFEASIBLE/UNKNOWN/MODEL_INVALID 直传 | R-ENG-01/02；PoC `allocation.py` |
| 2 | 只有固定月日 + 固定延迟 | 规则类型：固定日（当月/次月）、账单后 N 自然日/工作日；月末截断、闰年、跨年、账单日当天归属开关、顺延需已核验日历；入账窗口不确定时输出多个可能账期并按最早到期保守校验 | R-RULE-01~06；PoC `billing.py` |
| 3 | confidence 字段未参与模拟 | 事件类别 confirmed/expected/planned；已确认、基准、压力三类情景分别求解；预计收入不得进入"已确认"硬约束 | R-CASH-03/04；PoC `cash.py` |
| 4 | `as_of < event.day` 漏掉快照当天事件 | 快照记录 `includes_event_ids`；当天未标记包含的事件按未发生处理；同日顺序未知用保守顺序并记录假设 | R-CASH-06；PoC 测试 `test_same_day_event_not_in_snapshot_is_applied` |

| 6 | billing_rules/statements 挂在 cards | 账单与规则挂**信用账户**（必要时币种子账户），卡片只是支付介质；主附卡/换卡不复制账单 | R-CARD-02/03；`T-credit_accounts` |
