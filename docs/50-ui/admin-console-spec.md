# 50 · 维护后台规格（Web）

版本 0.1 · 2026-10-16 · 撰写：移动端体验与后台规格子代理 · 审定：Fable 主会话 · 状态：已完成（待实施）

适用自托管模式的响应式 Web 后台（桌面优先，React + Vite + TypeScript，A-04）；纯本地模式无后台（PRD §8）。服务只绑定 127.0.0.1，公网访问与反代由用户决定（A-15）。

**与 PRD 的对应关系**：R-SYS-12（后台范围与 RBAC，operator 不看账单正文）→ §1、AP-01~AP-08；R-RULE-02/04/05 与 `bank-rules-spec.md` §8 维护流程 → AP-02；R-PROMO-02/03/05、R-SEC-04 → AP-03；R-IMP-01~06 → AP-04；R-ARCH-05 → AP-05、AP-07；R-SEC-02、R-STMT-09"全部动作进审计"→ AP-06；R-SYS-05、R-DEL-05 → AP-07；R-SYS-07/09 → AP-08。身份与会话遵循 ADR-011，安全参数以 `60-ops-security/security-privacy.md` 为准。App 侧对应页面见 `ui-spec.md`（P-04、P-14、P-19、P-20）。

## 0. 原则

- 默认拒绝，最小权限；权限在 API 层强制，前端隐藏入口只是辅助。
- **用户财务正文**（账单版本金额与明细、交易、还款、现金事件、计划、导入抽取值、附件原件）对任何后台角色都不可见（数据库后台角色不授予正文列，security-privacy.md §4）；后台只展示元数据与聚合统计，正文只由数据所属用户在 App 内查看。
- 后台不预置任何银行规则或活动数值；取值只能经"来源附件 + 核验人"录入，字段语义以 `30-rules-engine/bank-rules-spec.md`、`30-rules-engine/promotions-benefits-spec.md` 为准。
- 四眼原则：起草人不能审核或核验自己的版本。
- 每个敏感操作写入只追加审计（AP-06）。

## 1. 角色与 RBAC

| 角色 | 定位 | 约束 |
|---|---|---|
| owner | 实例所有者（部署者）：系统配置、角色分配、备份恢复 | 至少 1 个；最后一个 owner 不可降级或删除 |
| admin | 维护者：审核、核验、发布规则/活动/模板，管理任务与设备 | 不能分配角色 |
| operator | 运营：起草规则/活动/模板，处理失败任务 | 默认只看元数据与统计，不可看账单正文 |
| auditor | 审计：只读审计日志与配置 | 不可修改任何数据 |

| 资源/动作 | owner | admin | operator | auditor |
|---|---|---|---|---|
| 分配/撤销角色、系统配置 | ✓ | ✗ | ✗ | ✗ |
| 规则/活动/模板：查看 | ✓ | ✓ | ✓ | ✓（只读） |
| 起草、编辑草稿、提交审核 | ✓ | ✓ | ✓ | ✗ |
| 审核、核验（非本人草稿） | ✓ | ✓ | ✗ | ✗ |
| 发布、失效、下架 | ✓ | ✓ | ✗ | ✗ |
| 来源白名单、许可与抓取频率 | ✓ | ✓ | 仅提议（admin 批准） | 只读 |
| 任务元数据 | ✓ | ✓ | ✓ | ✓ |
| 任务重试/取消 | ✓ | ✓ | ✓（不含删除类任务） | ✗ |
| 用户/设备元数据与聚合统计 | ✓ | ✓ | ✓ | ✓ |
| 撤销设备、禁用用户、处理删除请求 | ✓ | ✓ | ✗ | ✗ |
| **用户账单正文、交易、附件原件** | ✗（403 + 审计） | ✗（403 + 审计） | ✗（403 + 审计） | ✗（403 + 审计） |
| 审计日志查看 | ✓ | ✓ | 仅本人操作 | ✓ |
| 审计导出 | ✓ | ✗ | ✗ | ✓ |
| 备份触发 / 恢复 | ✓ / ✓ | ✓ / ✗ | ✗ | 仅查看状态 |

**正文隔离**：后台任何角色调用正文类接口一律返回 403 并写审计；排障需要数据时，由用户在 App 内查看或自行导出（P-20），后台不提供代查通道。

**聚合统计**：只给计数与分布，不含金额；任一分组样本 <5 时显示"<5"，防止反推个人数据。

## 2. 页面规格

### AP-01 登录与角色

| 项 | 内容 |
|---|---|
| 目的 | 后台认证、会话与角色管理 |
| 布局 | 登录（账号、口令；可选 TOTP）› 我的会话（设备、IP、最后活跃、「撤销」）› 成员与角色（owner 可见：邀请、改角色、停用） |
| 规则 | 账号体系按 ADR-011（argon2id 口令、短期访问令牌 + 刷新轮换 + 服务端撤销；参数见 security-privacy.md §4）；发布、失效、恢复、角色变更前须重新验证口令；TOTP 为可选增强，建议 owner/admin 开启；失败锁定与空闲超时阈值以 security-privacy.md 为准 |
| 状态 | 未登录 → 已认证（会话有效）→ 高危操作重新验证 → 超时/撤销 |
| 审计 | 登录成功/失败、锁定、二次验证绑定/重置（如启用）、角色变更、会话撤销 |
| 验收 | ① operator 登录后导航无正文类入口，直接调正文接口返回 403 且记审计（R-SYS-12）；② 最后一个 owner 不能降级或删除；③ 高危操作未重新验证时被拒 |

### AP-02 银行规则版本

| 项 | 内容 |
|---|---|
| 目的 | 维护可版本化、可核验的规则对象（字段模型见 `bank-rules-spec.md` §2） |
| 布局 | 规则列表（主体：银行/卡产品/账户模板；规则类型；版本；状态；生效区间；核验日；核验人）› 编辑器（按 schema 渲染字段，每字段可标"待核验"）› 来源附件（URL、截图/PDF、SHA-256 指纹、取得时间、`sources.md` S-ID）› 版本差异（字段级旧值/新值/来源变化）› 影响面（引用账户数，仅计数） |
| 状态机 | 草稿 draft → 审核 in_review → 已核验 verified → 已发布 published → 失效 expired；in_review 可退回 draft（附意见）；published 不可编辑，只能出新版本 |
| 校验 | 同主体同一时点只允许一个生效版本（区间不重叠）；固定日到期不晚于账单日 → 阻止；顺延须引用已核验节假日日历版本；核验人 ≠ 起草人；发布须至少一个来源附件且核验日不早于取得日；"待核验"字段可发布但在 App 显示"待核验"、引擎按保守处理；官方旧网页只作历史资料，不因仍可打开就视为现行 |
| 发布影响 | App 端"采用官方模板"的账户收到新版本；已出账单不改写（F-14）；引用该规则的方案标记过期（R-PLAN-07） |
| 审计 | 创建、编辑、提交、退回、核验、发布、失效、附件上传/删除 |
| 验收 | ① 本人草稿不能核验；② 无来源附件或区间重叠时「发布」不可用；③ 发布新版本后旧账单日期不变（F-14） |

### AP-03 活动版本与来源

| 项 | 内容 |
|---|---|
| 目的 | 管理活动来源白名单、抓取许可与活动版本复核（R-PROMO-02） |
| 布局 | 来源白名单（字段同 `promotions-benefits-spec.md` §10：domain、allowed_paths、license_note、robots_checked_on、fetch_interval_hours、last_fetch、status；另有来源类型 银行官方/卡组织/获许可数据源/用户分享，许可证明附件与使用范围 仅链接/摘要/全文）› 候选与版本（字段集见 `promotions-benefits-spec.md`；来源、核验时间、版本差异）› 复核队列 |
| 状态机 | 来源：提议 → 已批准 → 暂停 → 下架；活动版本：draft → in_review → verified → published → expired / withdrawn（下架，须理由） |
| 校验 | 未许可或 robots 禁止 → "自动抓取"开关不可开启，只允许保存链接与人工摘录；抓取间隔 ≥24 小时且不高于许可范围，默认手动；抓取只做变更检测与快照，解析为规则草稿须人工复核后发布，不执行任何脚本（R-PROMO-05）；仅白名单域名、禁止内网地址与跳转内网（SSRF，R-SEC-04）；活动时区必填；时间区间合法；条款未提及的字段保持"未提及"，不得补默认值；许可撤回 → 自动暂停抓取并提示下架 |
| 用户端联动 | published → App 活动库可见；withdrawn → App 显示"已下架（原因）"并撤销相关提醒，历史版本保留；expired → 仅历史可见 |
| 审计 | 来源提议/批准/暂停/下架、许可变更、抓取开关与频率变更、版本复核与发布 |
| 验收 | ① 未许可来源无法开启自动抓取（R-PROMO-02）；② S07 样本可无损录入并发布（F-40）；③ 下架后 App 不再发送该活动提醒 |

### AP-04 导入模板

| 项 | 内容 |
|---|---|
| 目的 | 维护 CSV 列映射、PDF/文本锚点、邮件解析等声明式模板（R-IMP-01、R-IMP-04） |
| 布局 | 模板列表（适用银行与账单类型、渠道、版本、状态）› 编辑器（列映射、日期/金额格式、正负号约定、编码、锚点）› 样本测试（字段命中、勾稽校验结果）› 版本差异 |
| 状态机 | draft → in_review → published → deprecated |
| 校验 | 模板无脚本；测试样本只允许合成或脱敏文件，含 ≥13 位连续数字即拒收；回归样本（含 F-47~F-50 场景）全部通过才能发布；发布不影响已入账批次 |
| 审计 | 模板创建、编辑、样本上传/删除、发布、弃用 |
| 验收 | ① 回归样本不通过时「发布」不可用；② 含 ≥13 位连续数字的样本被拒收；③ 新模板版本不改写已入账数据 |

### AP-05 任务与失败重试

| 项 | 内容 |
|---|---|
| 目的 | 处理解析、抓取、通知、备份、删除、求解等后台任务（PostgreSQL 任务表，A-04） |
| 布局 | 任务列表（类型、状态 queued/running/succeeded/failed/dead/cancelled、尝试次数、下次重试、耗时、错误码、脱敏摘要）› 详情（时间线、关联对象 ID）› 批量操作 |
| 规则 | 只显示元数据，不显示文件内容、抽取值、金额；错误摘要去除金额、邮箱与 ≥4 位连续数字，错误码单列；重试沿用原幂等键，不重复入账；退避与上限见 `deployment-ops.md`，超限转 dead 并告警；删除类任务仅 admin/owner 可操作 |
| 审计 | 重试、批量重试、取消、转 dead 的人工处理 |
| 验收 | ① 重试同一解析任务不产生重复批次（F-49）；② 错误摘要不含金额或卡号片段；③ operator 无法取消删除类任务 |

### AP-06 审计

| 项 | 内容 |
|---|---|
| 目的 | 记录并查询所有敏感操作（R-SYS-12、R-STMT-09） |
| 字段 | 时间（UTC，显示时区可选）、操作者、角色、来源 IP/设备、动作、对象类型与 ID、结果（成功/拒绝）、理由、变更摘要（字段名与哈希，不含正文金额）、请求 ID |
| 规则 | 只追加：数据库层禁止 UPDATE/DELETE；每条含前一条摘要形成哈希链，定时校验；导出动作本身入审计；用户删除后审计只保留哈希，与删除策略一致（R-SYS-09、security-privacy.md） |
| 布局 | 筛选（时间、操作者、动作、对象、结果）› 列表 › 详情 › 哈希链校验结果 › 导出（auditor/owner） |
| 验收 | ① 修改或删除审计记录被拒且产生一条拒绝记录；② 人为篡改一条后哈希链校验报警；③ operator 访问正文被拒的事件可在审计中查到 |

### AP-07 备份与系统状态

| 项 | 内容 |
|---|---|
| 目的 | 掌握服务健康与备份可恢复性（R-SYS-05） |
| 布局 | 系统状态（API、数据库、任务积压、求解 worker、磁盘、证书到期、各组件版本）› 备份（计划、最近成功、大小、校验摘要、仅显示密钥 ID、「立即备份」）› 恢复（演练/正式）› 告警 |
| 规则 | 正式恢复仅 owner：先在隔离 Compose 项目演练并出报告 → 二次确认并重新验证口令 → 恢复前自动快照；备份保留周期与演练频率按 security-privacy.md；密钥材料永不显示或下载；告警：备份失败、任务积压超阈值、磁盘不足、证书将到期 |
| 审计 | 手动备份、备份下载、恢复演练、正式恢复、保留策略变更 |
| 验收 | ① 备份校验摘要可被独立复核；② 非 owner 看不到恢复入口；③ 恢复演练不影响线上数据 |

### AP-08 用户/设备管理

| 项 | 内容 |
|---|---|
| 目的 | 管理用户与设备的元数据与删除请求（R-SYS-07、R-SYS-09） |
| 布局 | 用户列表（ID/别名、创建、最后活跃、设备数、存储用量、同步状态、删除请求状态）› 设备（平台、App 版本、最后同步、待推送数、「撤销」）› 删除请求（宽限期、状态、撤销记录）› 聚合统计 |
| 规则 | 不显示任何金额与正文；撤销设备后其下次同步被拒，App P-20 显示"本设备已移出同步"；删除请求按 30 天宽限期执行（security-privacy.md），期内用户可在 P-20 撤销；统计样本 <5 显示"<5" |
| 审计 | 设备撤销、用户禁用/启用、删除请求执行或撤销、正文接口拒绝 |
| 验收 | ① operator 页面不出现金额与正文字段；② 撤销设备后该设备同步返回 401/403；③ 删除请求在宽限期内被用户撤销后不再执行 |

## 3. 敏感操作审计清单

| 类别 | 必须记录的操作 |
|---|---|
| 身份 | 登录成功/失败、锁定、二次验证绑定/重置（如启用）、会话撤销、角色变更 |
| 规则/活动/模板 | 起草、提交、退回、核验、发布、失效、下架、附件变更 |
| 来源 | 白名单提议/批准/暂停/下架、许可与 robots 变更、抓取开关与频率变更 |
| 任务 | 重试、批量重试、取消、dead 人工处理 |
| 数据与隐私 | 正文接口拒绝（403）、删除请求处理、设备撤销、用户禁用 |
| 系统 | 备份触发/下载、恢复演练/正式恢复、保留策略与系统配置变更、审计导出 |

## 4. 后台通用状态

| 状态 | 展示要点 |
|---|---|
| 首次空白 | "还没有规则版本"「新建草稿」；不预置任何数值 |
| 加载 | 表格骨架；长任务显示进度 |
| 无权限 | 隐藏入口；直链显示"你的角色无权查看"并记审计 |
| 服务不可达 | 顶部提示，禁用写操作，保留草稿 |
| 错误 | 行内字段错误；服务端错误带请求 ID |
| 重试 | 「重试」幂等，任务按 AP-05 |
| 成功 | 写明结果，如"已发布 v3，App 下次同步获取" |
