## 2. 九态基线

| 状态 | 触发 → 展示与文案基线 |
|---|---|
| 首次空白 | 对象从未存在 → 图标+一句用途+主操作（可加「体验演示」）；金额位用"—"，不显示 0 |
| 加载 | 读取/计算 >300 ms → 骨架（减少动效时静态）；保留旧数据标"更新中"；求解显示阶段、时限与「取消」 |
| 无权限 | 系统权限被拒、服务端 401/403、设备被移除、演示限制 → 说明影响与替代，「去系统设置」/「重新登录」；不阻断本地功能 |
| 离线 | 自托管模式下网络或服务器不可达（纯本地不显示；R-ARCH-01）→ 横幅"离线 · 数据截至 {时间}"；本地写入照常并计"待同步 n"；服务端功能置灰并说明 |
| 余额陈旧 | 快照实际时点早于 stale_after_days（默认 7 天，R-CASH-09）→ 时钟图标+"{n} 天前"；依赖结果加"假设分析"；「更新余额」 |
| 数据不全 | 缺快照/规则/账单覆盖/汇率/字段 → 逐项列出可点补充；不补零；允许时「按假设继续」并持续标注 |
| 错误 | 校验、解析、本地库、服务端 5xx、完整性失败 → 行内或区块内显示，带错误码，说明已保留什么；不把半成品当结果 |
| 重试 | 可重试错误 → 「重试」+"第 n/3 次"+上次时间；同步自动退避；幂等键防重复提交 |
| 成功 | 动作完成 → ≤4 秒轻提示，可撤销的带「撤销」；文案带确认层级（"已登记（待银行确认）"，不写"还款成功"） |

叠加：错误、无权限为阻断态，占据对应区块；离线、余额陈旧、数据不全为叠加态，以横幅/徽标呈现，可并存。

API 错误码（`api-contract.md`）→ 九态：VALIDATION_ERROR、RULE_INVALID、FILE_REJECTED、IDEMPOTENCY_MISMATCH → 错误；UNAUTHORIZED、FORBIDDEN、CONSENT_REQUIRED、DEMO_RESTRICTED → 无权限；PARSE_TIMEOUT、RATE_LIMITED → 重试（退避）；NEEDS_DATA → 数据不全；BASELINE_SHORTFALL、SOLVER_INFEASIBLE、SOLVER_UNKNOWN、MODEL_INVALID → §5 状态页；VERSION_CONFLICT → P-21；DUPLICATE_DOCUMENT → 提示"已导入过，未重复入账"；NOT_FOUND → "已不存在"。

## 3. 设计规范

### 3.1 语义色 token

对比度按 WCAG 2.x 相对亮度公式实算，取前景对自身底色、surface、canvas 的最小值并向下取一位小数。

| Token | 用途 | 浅色 前景/底色 | 深色 前景/底色 | 最低对比度 | 必配图标+文字 |
|---|---|---|---|---|---|
| text.primary / text.secondary | 正文与金额 / 辅助 | #1A1C1E / #575C63 | #E6E8EB / #A8AEB6 | 13.6 / 6.2 | — |
| surface / canvas | 卡片 / 页底 | #FFFFFF / #F5F6F8 | #1B1E22 / #101214 | — | — |
| action | 主按钮、链接 | #1F5BB8（按钮白字） | #8AB4F8（按钮字 #0B1D3A） | 5.9 | — |
| risk.robust | **仅** FEASIBLE_ROBUST | #146C36 / #E5F3EA | #6FD394 / #12301E | 5.6 | 盾牌勾"稳妥" |
| risk.attention | 有条件可行、需要数据、陈旧、数据不全、待核对 | #7A4D00 / #FFF2D1 | #F2C14E / #3A2B07 | 6.5 | 半盾/清单/时钟 |
| risk.danger | 基线缺口、无解、缺口、逾期、失败 | #B3261E / #FCE8E6 | #FF8F85 / #3D1512 | 5.5 | 三角叹号/禁止 |
| risk.unknown | 未判定、资格待确认 | #4B5059 / #ECEEF1 | #C2C7CF / #2A2E34 | 6.9 | 沙漏/问号 |
| risk.defect | 模型异常、系统缺陷 | #7B2D8F / #F4E8F7 | #E2A8F0 / #36183F | 6.7 | 扳手 |
| confirm.bank | 银行确认 | #1C4FA0 / #E6EEFA | #9DBEFF / #14284A | 6.7 | 印章勾"银行确认" |
| demo | 演示横幅 | #FFFFFF 于 #4A2E8C | #1D1238 于 #CBB7FF | 9.8 | 烧瓶"演示数据" |
| border.input | 输入框与控件边 | #7C828A | #7D848D | 3.5（非文本 ≥3:1） | — |

规则：每个状态同时有图标、文字与颜色，灰度或色觉模拟截图下仍可区分（R-UI-03、R-UI-05）；负数用"−"加语义词（缺口/超限/贷方余额）；图表缺口点用 ▲ 加标签；新增颜色须过同一对比度脚本。

### 3.2 间距（4pt 网格）

所有尺寸取 4 的倍数：4（图标与文字）、8（相邻可点元素最小间隔）、12（行内分组）、16（页边距、卡片内边距）、24（区块）、32（大区块）；圆角 4/8/12，图标 16/20/24，列表行最小高 48。

### 3.3 字号阶梯与大字号

| 样式 | 字号/行高 pt | 用途 |
|---|---|---|
| num.display | 32/40 Semibold 等宽 | 总览主数字 |
| title.l / title.m | 24/32、20/28 Semibold | 页面 / 区块标题 |
| body.l / body.m | 17/24、15/20 | 正文与表单 / 列表次行 |
| label / caption | 13/16 Medium、12/16 | 徽标 / 时间与来源（caption 不承载唯一关键信息） |

大字号：跟随 iOS 动态字体与 Android 字体缩放，不做低于 2.0 倍的钳制；200% 时金额与状态换行而不截断；≥130% 时双列改单列、表格改堆叠卡片；文本容器不设固定高度。

### 3.4 数字与金额（R-UI-05）

- 数字一律等宽（tnum）；金额右对齐、小数点对齐、千分位。
- 整数最小单位存储，按币种小数位展示（CNY 2、JPY 0、KWD 3）；CNY 用"¥"，其他用 ISO 代码；不同币种不相加，折算标"≈折算（汇率来源、时间）"，汇率未知显示"汇率未知"且不计入合计。
- 负数用"−"（U+2212）；不确定日期写"11-28 或 12-08（可能账期）"；按账户业务时区显示，与设备不同时附"按 {时区}"；估计值加"预计"并虚线描边；"名义（月费率×12）"与"实际年化（复利）"分列。

### 3.5 可访问性（R-UI-05）

| 项 | 规则 |
|---|---|
| 对比度 | 文本 ≥4.5:1（大字不放宽）；非文本控件与焦点环 ≥3:1 |
| 触控 | ≥44×44pt（Android ≥48dp），相邻间隔 ≥8 |
| 读屏 | 可交互元素均有标签；金额读"本期应还 人民币 8,000 元"；徽标读文字；图表有表格替代与一句摘要；求解完成播报业务状态 |
| 焦点 | 同视觉顺序；弹层打开时进入、关闭后回到触发点 |
| 减少动效 | 跟随系统，可在 P-19 强制；关闭视差、骨架闪烁、数字滚动、图表生长；转场 ≤150 ms 淡入或无 |
| 操作替代 | 长按、滑动均有按钮或读屏自定义动作替代 |

### 3.6 金额隐藏与锁屏隐私（R-UI-08）

| 机制 | 规则 | R-ID |
|---|---|---|
| 金额隐藏 | 全局开关（P-19、顶栏眼睛）；金额一律显示固定 4 个"•"，不随位数变化；图表数值轴、提示框、导入文件名同隐藏；读屏读"金额已隐藏" | R-SYS-03 |
| 临时显示 | 长按单个金额显示，松开或 5 秒后恢复，不改全局开关 | R-SYS-03 |
| 锁屏保护 | 生物识别/设备密码；超时 立即/1/5/15 分钟；锁定时不渲染金额 | R-SYS-04 |
| 任务切换遮罩 | 进入后台立即覆盖遮罩（图标+"卡序已隐藏"） | R-SYS-04 |
| 通知 | 默认只含账户别名（末四位可配置）与事件类型，不含金额；用户在 P-18 显式开启才含 | R-NOTIF-04 |

## 4. 全局交互规则

### 4.1 外链策略（R-UI-04）

| 情形 | 行为 |
|---|---|
| 有可用且经验证的官方链接（来源记录已核验/已发布、域名在后台白名单、https、核验未过期） | 「去还款/去报名/去预约/去领取」→ 确认页（目标域名、"官方链接 · 核验于 {日期}"、"卡序不会代你付款或报名"）→ 系统浏览器或已核验 App 链接；URL 不带金额与个人信息 |
| 无链接、未核验、已过期、打开失败、演示模式 | 不跳转；按钮改「查看操作说明」：显示规则/活动记录中的说明，无记录时"请通过发卡行官方 App、官网或客服办理"；提供「复制金额」「复制末四位」 |
| 回到 App | 询问实际结果，不自动标记：还款「已发起」(processing)/「我已还款」(user_marked_paid)/「还没有」/「遇到问题」；报名「报名成功」(enrolled)/「未成功」；预约「已预约」(reserved)/「未预约」；领取「已领取」(reward_claimed) |
| 层级 | 以上选择最多为"你已确认"；"银行确认"只来自账单、流水或截图证据 |

### 4.2 演示模式（R-SYS-13）

- 数据：独立 demo 工作空间；合成样本（卡 A/B/C，固定"今天"=2026-10-16，不判陈旧）；规则与活动标"仅示例"。
- 标识：每页顶部常驻紫色横幅（烧瓶图标+"演示数据 · 与真实数据隔离"+「退出演示」），不可关闭。
- 禁止：同步、备份、导出、合并到真实空间、外链跳转、系统通知（只进消息中心并标"示例"）、服务端解析与求解。
- 真实↔演示切换须确认；两空间的搜索、统计、消息互不可见；「清除演示数据」一键清空。

### 4.3 确认层级（R-UI-07）

| 层级 | 样式与文案 | 来源 |
|---|---|---|
| system_estimated | 虚线描边+计算器图标"系统估计" | 规则预测、引擎、活动进度 |
| user_confirmed | 实线描边+人形勾"你已确认" | 用户操作（含外链返回） |
| bank_confirmed | confirm.bank+印章勾"银行确认" | 账单、流水、截图核对 |

### 4.4 通用字段校验（各页以 G1~G5 引用）

- G1 金额：整数最小单位，按币种小数位输入；默认 >0，明确允许时可负。
- G2 敏感数字：任何文本含 ≥13 位连续数字（含粘贴）拒绝保存并提示"卡序不保存完整卡号"；不设 CVV/PIN/验证码/网银密码字段（R-CARD-02）。
- G3 时间：实际发生或观测时点 ≤ 现在；带精度（日/时刻）与业务时区。
- G4 币种：ISO 4217；未知汇率不当 0。
- G5 文本：名称 ≤20 字、说明 ≤200 字。

### 4.5 敏感操作与禁用文案

- 删除、撤销批次、销卡、抹除：确认页写明影响数量；抹除另需设备认证并输入"删除"；可撤销操作给 4 秒「撤销」；改账单金额只生成新版本（R-STMT-07）。
- 未达 FEASIBLE_ROBUST 不出现"稳妥/安全/推荐/放心"与绿色勾；全 App 禁用"已实时同步银行"、无银行确认的"还款成功"、"再消费 X 元可达标"、借款/提额/以卡养卡建议、免息未核验时的"零成本"。

## 5. 引擎状态 → UI 映射（R-PLAN-08）

### 5.1 业务状态（主状态：决定颜色、图标与标题）

| 业务状态 | token/图标 | 标题文案 | 必须展示 | 允许动作 | 禁止 |
|---|---|---|---|---|---|
| NEEDS_DATA | attention/清单 | "需要补充数据才能计算" | 逐项缺失（缺快照、快照 {n} 天前、规则非法、池缺快照、缺汇率）及影响 | 「去补充」（深链 P-04/P-08）；「按假设继续」（确认页列出假设，此后结果全程带"假设分析"） | 方案卡；绿色 |
| BASELINE_SHORTFALL | danger/三角 | "新增消费前已有资金缺口" | 账户、首个缺口日、最低点金额与日期、距零与距储备缺口、导致缺口的事件 | 「查看资金日历」（定位）「调整收支」「补充已确认资金」「调整储备」（写入 reserve_override） | 方案卡 |
| INFEASIBLE | danger/禁止 | "{情景}下没有满足全部约束的组合" | 首个缺口日、账户、现金缺口与距储备缺口；逐卡拒绝原因；敏感性三项：最少补充已确认现金（按账户）、最大可负担金额、最早可行日期 | 「按敏感性调整」（预填 P-10，不自动提交）「换情景」「存草稿」 | 方案卡；借款/提额/以卡养卡建议 |
| UNKNOWN | unknown/沙漏 | "未能在时限内判定"，副标题"这不代表没有可行组合" | 时限与用时；本地有限搜索结果（若有，标"本地找到，未证最优"） | 「延长时限重试」「减少约束」（K、最小拆分）「联网完整求解」 | "无可用组合"类文案 |
| MODEL_INVALID | defect/扳手 | "计算异常，已停止展示方案" | 原因码：输入非法→定位字段；VERIFIER_REJECTED_SOLVER_SOLUTION→"系统缺陷，已记录"；run_id | 「修正输入」「复制诊断信息」（仅 run_id、input_hash、版本号） | 任何分配结果 |
| CONDITIONALLY_FEASIBLE | attention/半盾 | "有条件可行：{n} 个情景未通过" | 每个未通过情景（含已确认口径）的最低现金、日期、距零/距储备缺口；未通过压力情景的敏感性 | 查看、保存、采纳（须勾选知情确认） | 绿色；"稳妥/安全/推荐" |
| FEASIBLE_ROBUST | robust/盾牌勾 | "稳妥：所有情景（含已确认口径）均通过" | 各情景最低现金与日期、最差余量、关键假设 | 采纳、保存 | — |

合成样本文案（引擎 §9）：有条件可行——"2 个情景未通过 · 已确认口径：新增消费前 11-08 已缺 2,000 · 压力（收入推迟至 11-29）：11-28 缺 2,000，距储备缺 4,000"；压力情景作决策情景时无解——"最少补充已确认现金 4,000 · 最多可负担 6,000 · 推迟 5 天（10-21）可行"。

### 5.2 求解器状态（副标签，不改变颜色）

| 求解器状态 | 副标签 | 详情区 |
|---|---|---|
| OPTIMAL | "已证最优" | 当前画像分层目标下已证明最优；不代表资金稳妥 |
| FEASIBLE | "可行，未证最优" | 时限内找到解；显示各层状态与 bound |
| INFEASIBLE | "已证明无解" | 只与业务 INFEASIBLE 同现 |
| UNKNOWN | "时限内未判定" | 上层已有解时保留并标"第 {n} 层未完成" |
| MODEL_INVALID | "模型校验失败" | 同业务 MODEL_INVALID |
| 本地有限搜索 | "本地有限搜索（K≤3，≤2 秒）" | 找到→"可行，未证最优"；未找到→"本地未找到（非证明无解）"，按 UNKNOWN 样式 |

组合规则：① 颜色与标题只由业务状态决定，OPTIMAL 不能让 CONDITIONALLY_FEASIBLE 变绿；② FEASIBLE_ROBUST + FEASIBLE → 绿色"稳妥"+副标签"未证最优"；③ "按假设继续"得到的任何状态都追加"假设分析"标签与假设清单；④ 方案过期（R-PLAN-07）覆盖一切状态：灰化+"已过期：{快照/事件/规则版本变化}"，只保留「重算」「查看历史」；⑤ 资金不足类状态必须给出金额、日期、账户与原因事件；金额隐藏时以"••••"占位，原因文字照常。
