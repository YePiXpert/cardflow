## 3. Opus 子代理任务边界

每个 WP 的简报必须包含：目标与 R-ID；要读的文档路径（PRD 段、规格、数据模型表、API 条目、fixtures）；禁止事项（不改其他模块、不改金额语义、不引入未核验依赖、不用 float、不写"生产启用 RLS"注释代替实现）；交付物路径；测试命令与期望输出；证据输出位置。子代理不得：修改 ADR、修改协议版本、跳过 fixture、把 mock 当完成、声称真机验证而无记录。

## 4. 交叉审查方案

1. **实现者 ≠ 审查者**：每个 WP 由一个实现子代理完成后，由另一个"新鲜上下文"审查子代理按清单审查（S14 建议），输出发现清单；主会话裁决。
2. **审查清单**：R-ID 覆盖；fixture 通过且有输出；金额/时间语义；错误状态不被吞掉；RLS/幂等；日志无 PII；文档与代码一致；追踪矩阵更新。
3. **主会话验收**：对照退出条件逐项核对工具输出（测试日志、`/readyz`、安装记录）；没有工具输出的声明不计入完成。
4. **财务模块双审**：WP-11/12/13/20 额外做性质测试审查与边界样本抽查。

## 5. 完成定义（DoD）

| 维度 | 必须提供 | 不接受 |
|---|---|---|
| 源码与迁移 | 可运行；`alembic upgrade head` 空库通过；回滚测试 | 只有 DDL 文本 |
| 功能 | 按钮对应真实逻辑与持久化；重启不丢；模块连通 | mock 接口、硬编码样本 |
| 测试 | 单元/性质/DB/API/移动端关键流程/迁移/备份恢复/权限隔离的可复核记录 | "测试全过"口头声明 |
| 移动端 | Android release APK + 测试密钥签名安装与覆盖升级记录、用户自签安装确认；iOS Mac 构建记录 + 用户自签真机安装记录，或"待外部凭证"标注 | 编译通过截图 |
| 自托管 | 部署版本、`/readyz`、迁移版本、恢复演练报告 | Compose 草案 |
| 外部接入 | 真实授权/响应或明确"不可用" | 随机生成数据 |
| 状态 | 追踪矩阵区分 已完成/已验证/待外部凭证/未实现 | 无证据的 100% |

## 6. 风险登记

| 风险 | 影响 | 缓解 |
|---|---|---|
| drift 加密钩子真机问题 | M0 延期 | 回退 sqflite_sqlcipher（ADR-001） |
| 无 Mac 环境 | iOS 构建阻塞（自签也需在 Mac 上构建） | 并行推进 Android；iOS 列待外部凭证；可用 Mac CI 服务（用户决定） |
| 招行规则正文缺失 | 招行计息精度 | 规则 pending 状态 + 用户提供文本 |
| 中文 OCR 准确率 | 导入体验 | 文本层优先；校对 UI；模板 |
| 同步冲突复杂度 | M4 延期 | 冲突外显而非自动合并；范围控制 |
| 更换签名身份 | 无法覆盖安装；本地数据与数据库密钥丢失 | 签名说明要求长期固定签名身份；更换前先备份或同步，按 UF-9 恢复；TC-MOB-14（ADR-015） |
| iOS 自签描述文件过期 | App 无法启动（数据仍在） | 用同一 Apple ID 重签后覆盖安装；付费个人账号有效期更长（用户决定） |
| App Review 法人要求 | 仅在将来上架时 | v1 不上架（ADR-015）；上架时再评估 |
