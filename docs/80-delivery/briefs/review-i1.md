## 重点（按风险排序）
1. **数据丢失与迁移**：从 v1（公测前 IPA 4d720c9 的库）、v2、v3 升级到 v4 的每条路径，冻结 SQL 与 drift 定义是否一致、迁移与 `user_version` 是否同事务、失败是否整体回滚、升级后旧行是否完好；「清除演示数据」「重置本地数据」「删除账户/卡/事件」是否可能删到真实空间或别的行；外键是否真的开启；软删除后读模型是否一致。
2. **工作空间隔离**：每个仓库查询与 provider 是否按当前空间过滤；复合外键是否挡住跨空间关联；切换空间时缓存是否失效（provider 依赖）；演示空间写入能否漏进真实空间。
3. **金额与日期正确性（App 层映射）**：账期归属（`resolveCycle`、可能账期、截止时点、业务时区）；负债四分法不重复相加；分期各期本金、费用、尾差、各期账单日；分期成本名义与实际年化（与 Python `money.py` 对照）；还款状态机 PRD §6.3 全部转移与非法转移拒绝；双侧时间 F-31（现金按扣款日、负债按入账日）；额度释放 F-28；疑似重复 F-32 只核销一次；分配合计 F-33；退款 F-34；贷方余额 F-38；现金时间线与情景（F-01~F-07）。用合成数据构造边界用例：月末、闰年、跨年、时区边界、同日多事件、金额 10^13 附近、负可用额度。
4. **追加只读与触发器**：`statement_versions` 金额列 UPDATE 被拒；任何仓库路径能否绕过（直接 UPDATE、删除后重建、改 current_version_id 指向）；`linked_repayment_id` 约束；状态机触发器与仓库层规则是否矛盾。
5. **界面规则与隐私**：禁用文案（"还款成功"、"安全"、"稳妥"）与无缺口时不用绿色；金额只经 MoneyText（隐藏开关是否覆盖新页面）；G2 完整卡号拒绝是否覆盖全部自由文本（商户、标签、备注、证据备注、修正理由、情景名、账户名）；诊断日志与报告不含金额、正文、卡号数字；公测说明与「关于」文案与实际行为一致（数据只在本机、删除即永久删除）。
6. **公测用户的首次体验**：全新安装 → P-22 → 手工建卡与体验演示两条路径是否都能走通、没有死路；空状态、错误态是否给出下一步；3 倍字号下关键页面不溢出；大数据量（例如 20 张卡、两年交易、500 条现金事件）时首页与资金日历的计算耗时（`flutter test` 里测，给出数字）。
7. **CI 与发布**：`mobile.yml` 的 action 是否全部固定 SHA、产出数断言是否真的会在少产出时失败、Required Reason 扫描是否覆盖全部二进制、`Verify IPA` 的图标与版本检查；有没有 `continue-on-error`、`|| true` 掩盖失败。
8. **公开仓库卫生**：apps/mobile、evidence/i1、.github、docs/90-promo（若已合入）内是否出现宿主服务/端口清单、口令、令牌、邮箱、真实卡号样式的数字。
9. **证据是否能支撑结论**：evidence/i1/I1-a、I1-b、I1-c 是否与各简报的验收清单一致、是否为工具原文、命令能否复现。

## 分级
- **blocker**：金额/日期算错、数据丢失或误删、跨空间泄露、密钥或个人数据泄露、追加只读可绕过、CI 可能在失败时显示绿、公开仓库泄露。
- **major**：现实输入下行为错误、公测用户会卡住的死路、测试缺口掩盖了缺陷、文档与实现矛盾且会误导用户或 I-2。
- **minor**：风格、命名、注释、可读性、非阻塞改进。
每条发现：编号、级别、文件:行、现象、复现方式（命令或测试片段）、建议修法。拿不准的标"疑问"而不是定级。
