## 主会话裁决（必须照此实现）
1. **账单接续与本期剩余应还（R-02，Q-4）**：按 PRD §6.2 裁决段在读模型实现，存储状态与触发器不变。
   - 同一币种子账户里最近一期账单是"本期"；更早的账单显示"已并入 {下一期账单日} 账单"，不计入总负债与本期应还、不进近期到期、不标逾期、不接受新的分配。
   - 本期剩余应还 = 本期当前版本的新增账单 − 入账日晚于本期账单日的银行已入账还款（不论分配到哪一期）± 第 2 条的转分期调整。入账日不晚于本期账单日的还款不再扣减。
   - 分配：同一币种子账户的还款只分配到"本期"；登记表单默认分到本期并预填剩余应还；超过剩余应还时要求确认（多还的形成贷方余额）。已存的、分配到旧账单的数据照常读出，金额按入账日期计算，不按分配计算。
2. **已出账消费转分期（R-01）**：允许（账单分期很常见）。若该消费已计入某期账单 S 的新增账单，且 S 的当前版本录入时间早于分期计划建立时间，则 S 的剩余应还 − 分期本金 + 账单日等于 S 账单日的那一期（本金 + 手续费）；之后录入的修正版本视为已反映分期，不再调整。"未来分期本金"只计账单日晚于本期账单日的各期。
3. **有效状态（R-03，R-06，Q-5）**：剩余应还 > 0 → 未过到期日为"待还"（有入账还款时为"已还一部分"），过了到期日为"已逾期"；≤ 0 → 有银行确认为"已还清"，只有入账未确认为"已入账（待银行确认）"，因转分期而为 0 时为"已转分期"；< 0 显示贷方余额。冲正、人工修正、删除交易、作废分期后自动重新推导。近期到期、逾期提醒、账单中心、P-01、P-03 一律用有效状态；仓库里依赖存储状态的规则（如"已结清不能修正"）改看有效状态。读模型只读，不在读取时写库。
4. **分期成本（R-04）**：条款不可改，成本按计划算一次并缓存（provider 按计划 id 记忆化）；转分期表单的预览去抖（≥ 300 ms）并用 `Isolate.run` 计算；界面线程上不做 IRR。领域包的 IRR 提速留到 I2-0。
5. **撤销入口（R-16、R-07、Q-3）**：交易行加「删除」（已转分期的先提示作废分期）和「补入账日」；可能账期跨过本期账单日、入账日未知的交易标"可能已出账，请补入账日"。分期卡片加「作废（录错了）」。都调用已有的仓库方法。删除、作废、修正之后，由系统把引用它的未处理差异项标为已处理并写明原因（`resolved_by = system`）。
6. **演示 → 真实写入（R-15）**：切换工作空间（进入或退出演示、切换空间）后统一回到首页并清空页面栈；表单打开时记下工作空间 id，保存时不一致就拒绝并提示。
7. **R-08**：删除子账户前检查交易、账单、还款、分期，给出说明；异常包装为 `RepositoryException`。
8. 不变：表结构（v4）、触发器、领域包、协议包、版本号（0.0.2 由 U-1 改）。
9. **CI（R-11）**：`Verify IPA` 断言 `CFBundleShortVersionString` 等于 pubspec 版本名、标签构建时等于标签去掉 `ios-v`、`CFBundleVersion` 等于 `run_number`；Required Reason 扫描对"需要由 App 清单承担、App 清单却未登记"的类别 `exit 1`；flutter-action 的内部缓存：优先改为 `cache: false`，再用固定 SHA 的 `actions/cache` 自行缓存 Flutter SDK；做不到就在 README 写明接受这一残余。
