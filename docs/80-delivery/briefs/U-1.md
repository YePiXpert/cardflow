# 简报 U-1 · 公测版 0.0.2：卡账首页与界面重做

派发：I-1 阶段末审查（`briefs/review-i1.md`）交回、主会话裁决之后。若审查有 blocker/major，主会话先另派修复任务或把修复项追加到本简报末尾的"审查带入项"再派发。若需重新派发，在开头加一句"先核对磁盘与 git 现状，不要重复创建"。

## 背景
用户 2026-10-19 装上 0.0.1 后的反馈："界面太丑，没有使用欲望"。用户拿正在用的信用卡小程序对比："虽然不好看，但是能看出多少钱和日期"——它的首页每张卡一行：账单金额、待还金额（大字）、"N 天后出账 + 日期"、"N 天后还款 + 日期"（大号数字），顶部有总授信额度和"3 天内待还 N 笔"、"免息最长的卡"。

0.0.1 的问题见 `docs/50-ui/mockups/0.0.2/README.md`。**设计稿**：`docs/50-ui/mockups/0.0.2/` 的 `home-dark.png`、`home-light.png`、`card-dark.png`、`cash-dark.png`（用 Read 工具直接看图；源文件 `mock.html`）。目标：**打开就能看到每张卡欠多少、哪天出账、哪天还款**；视觉上整洁、有层次、数字醒目，比小程序好看。

## 2. 卡账首页（`home-dark.png` / `home-light.png`）
数据口径（新增一个可单测的读模型，例如 `LedgerHomeReader`，不要把计算写在 widget 里）：
- **行**：每个未关闭信用账户的每个币种子账户一行；已冻结的显示"已冻结"标签。名称 = 银行简称（去掉"银行"二字）+ "···· 主卡末四位"，右侧产品名。
- **待还**（大字）= 最近一期已出账单的剩余应还（与 `LedgerReader` 同一口径：只扣银行已入账的还款）。状态标签至多一个：已结清（银行确认）→"✓ 已还清"（银行确认蓝）；部分 →"已还一部分"（注意色）；用户已标记 →"已标记还款"（中性）；过了到期日仍未结清 →"已逾期"（危险色）。没有已出账单 → 待还显示"—"，下方小字"未出账 ¥x"。
- **账单** = 最近一期账单当前版本的新增账单金额（小字）。
- **N 天后出账** = 按账期规则从今天起的下一个账单日（领域包算，含当天归属规则）；当天 →"今天出账"。
- **N 天后还款** = 未结清账单的到期日；当天 →"今天还款"（注意色）；已过 →"已逾期 N 天"（危险色）；已结清或没有未结清账单 → 下一期的预测到期日，用次要文字色。
- **没有账期规则** → 两个日期格改为一个"设置账期 ›"入口（去 P-04）。
- **排序**：默认按还款日（未结清的按到期日升序在前，已还清/无待还的按下一期到期日在后，没有规则的最后）；"排序"菜单另有按出账日、按待还金额。
- **顶部汇总卡**：本期待还合计（按币种分别合计，人民币大字，其他币种一行小字；不同币种不相加）、"N 张卡"、"最近 MM-DD 到期 · 银行 ¥x"；"3 天内到期 N 笔"；"总额度" = 人民币当前总额度，授信池只算一次池上限；"可用" = 领域包 `capacityLayers` 口径的人民币可用合计（池只算一次）。有账户缺额度快照时写"部分卡缺额度"，不以 0 代替。
- **今天刷哪张**：候选 = 未冻结、有有效规则、可用容量 > 0 的人民币子账户。对每个候选用 `forecastCycles(versions, 今天)` 的 `conservative` 账期（入账延迟不确定时按最早到期，保守），免息天数 = 到期日 − 今天。取天数最大的；并列时可用容量大的在前，再按名称。显示徽标、"今天刷 {银行} ···· {末四位}"、"MM-DD 出账 · MM-DD 还款"、大字"N 天免息"。点开是底部弹层：前 5 名候选与各自天数，以及口径说明（按今天入账计算；入账可能延迟时按最早到期；不考虑活动、手续费与额度是否够用）。没有候选时整块不显示。
- **待处理**：待核对的还款与差异项合计 > 0 时，在汇总卡下面显示一行"N 项待处理 ›"，进原有页面；为 0 时不显示。
- **给贷款留位置**：用户另有消费贷（PRD R-CASH-11，简报 `L-1.md` 在本任务之后做，设计稿首页底部的"贷款"分组）。首页读模型与布局按"分组"设计（信用卡、贷款……），汇总卡能再加一行；本任务不实现贷款。
- 空状态：真实空间还没有卡 → 大号"添加第一张卡"按钮与"体验演示"入口；P-22 仍是首次启动页。
- 演示数据的银行名改成互不相同的虚构名称（例如星海银行、长江银行、北辰银行），让首字徽标区分得开；改动时同步测试。

## 3. 卡片详情（`card-dark.png`）
- 卡面头部：银行色渐变、银行名、产品与主/附卡、"···· 末四位"、额度条（已用/总额度）、"额度 ¥x · 可用 ¥y"。
- 本期进度：出账日 → 今天 → 还款日的进度条，"还剩 N 天还款"/"今天还款"/"已逾期 N 天"；没有已出账单时显示"下期 MM-DD 出账 · MM-DD 还款"（预测）。
- 金额区：待还（大字）与最低还款；本期账单；未出账（N 笔）。
- 三个主按钮：登记还款（主色）、记一笔、更新额度；"⋯"菜单放录入正式账单、人工修正、换卡/补卡、冻结、销卡、账期设置。
- 下面依次：账单历史（每行一个状态标签）、分期摘要（"第 k/n 期 · 每期 ¥x"）、可折叠的"负债明细"（原负债四分法）、卡片列表、账期规则、授信池。
- **记本期账单**（快捷）：底部弹层，字段 = 账单日（默认今天及以前最近的预测账单日）、新增账单金额（必填）、最低还款（可选）、到期日（默认预测值，可改）；用现有仓库生成 v1 手工账单，其余要素按"来源未含此项"保存。原"录入正式账单"完整表单保留为"完整录入"。
- **还清本期**（快捷）：预填金额 = 剩余应还、分配 = 本期账单、方式手工、发起时间 = 现在、扣款账户 = 唯一可用于还款的现金账户（多个时让用户选），生成"已登记"的还款；之后在详情与卡账行上用一步操作推进"银行已入账""银行确认"。状态机与文案规则不变（不出现"还款成功"）。

## 4. 现金（`cash-dark.png`）
- 顶部：7/30/90/180 天分段控件；口径（已确认/基准预期/情景）收进一个紧凑菜单。
- 余额曲线（`CustomPaint`）：所选账户（默认最差的那个）逐日最低余额的折线与面积；0 线、储备虚线、缺口段标危险色并有 ▲ 与日期；起止日期标注。带 `Semantics` 文字摘要（"30 天内最低 −¥3,200，11-15，工资卡；缺口 1 处"）。"表格"切换回原来的日行表。
- "接下来"：未来收支与还款列表（日期块、名称、账户、金额），缺口点穿插其中。
- 下面是现金账户与收支计划（原 P-08 内容，按新样式）。语义不变：逐账户计算、账户之间从不相加、没有缺口不用绿色。

## 5. 视觉规范
- **颜色 token 更新**（深色/浅色）：背景 `#0B0D10`/`#F2F3F6`；表面 `#16191E`/`#FFFFFF`；次级表面 `#1E2228`/`#F6F7F9`；分隔线 `#262B33`/`#E8EAEE`；主文字 `#F2F4F7`/`#15181C`；次要文字 `#9AA3AE`/`#5F6874`；第三级 `#6B7480`/`#8A929C`；强调 `#5B9BFF`/`#1F5BB8`。注意、危险、银行确认、演示四类语义色沿用 ui-spec 的色相，背景用浅色调。`ColorScheme` 的 surfaceContainer 各级映射到不同的层次，不要全部等于 surface。文字对比度 ≥ 4.5:1（两种模式都核对，不够就调色并记偏离）。
- **字体与数字**：大标题 32/粗、分组标题 17/粗、正文 15、说明 12；金额 38（汇总）/30（详情）/24（列表行），一律等宽数字（tabular figures）。用系统字体，不打包字体。
- 圆角 18–22，页面左右边距 16；每行至多一个状态标签；"负债四分法""差异""确认层级"等术语只在详情页出现（首页用"负债明细""待处理"）；长说明收进"ⓘ"弹层。
- **银行徽标**：34pt 圆角方块、白色简称首字；常见银行（工、建、农、中、交、招、浦发、民生、兴业、光大、中信、平安、广发、华夏、邮储、浙商）给固定品牌色，其余按名称哈希取调色板；白字对比度 ≥ 4.5:1。
- **动态字体**：2–3 倍字号时列表行改为纵向排列（金额在上，两个日期格在下），不溢出、不截断金额；可访问性测试必须覆盖新页面。
