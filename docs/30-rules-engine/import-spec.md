# 32 · 导入与解析规格（手工 / CSV / PDF / 文本 / 截图 / 邮件文件）

版本 0.1 · 2026-10-16。对应需求 R-IMP-01~09、R-STMT-07/09。平台限制依据 S04/S05/S06。

## 1. 渠道与入口

| 渠道 | 入口 | 解析位置 | 输出 |
|---|---|---|---|
| 手工 | 表单 | — | 直接生成实体（仍走校验） |
| CSV | file_picker / 系统分享 | 设备端（模板映射） | 交易/账单明细候选 |
| PDF（文本层） | file_picker / 分享 | 设备端 pdfrx 文本层；联网可选服务端 pypdf/pdfplumber | 账单要素 + 明细候选 |
| PDF（扫描）/图片 | 同上 | 设备端 ML Kit 中文 OCR；联网可选服务端 rapidocr | 候选（低置信度） |
| 纯文本/粘贴 | 文本框 | 设备端正则模板 | 候选 |
| .eml / HTML | 分享/文件 | 设备端标准库解析正文与附件 → 走 PDF/HTML 管线 | 候选 |
| 指定邮箱授权导入（可选） | 设置页授权 | 服务端周期拉取 | 创建批次 |
| Android 短信（可选 flavor） | 系统权限 | 设备端 | 交易提醒候选 |

## 2. 解析顺序与隔离（R-IMP-02/03）

1. 类型嗅探（magic bytes）与大小限制（≤25 MB）；压缩包只列出条目供用户选择，不递归解压。
2. PDF：加密→请求用户密码（内存，解析后清除，不写日志/不同步）；先取文本层；文本层为空或字符数 < 阈值才 OCR。
3. HTML：净化（移除 script/iframe/外链资源），禁用网络加载。
4. 超时：设备端 60 s、服务端 120 s；失败可重试 3 次；批次状态 `failed` 可见原因。
5. 重复文件：sha256 命中→提示"已导入于 …"，允许作为新版本或放弃。
6. 恶意样本集（F-47）：畸形 PDF、JS PDF、超大页、zip 炸弹、路径穿越文件名、伪装扩展名。

## 3. 抽取候选与置信度（R-IMP-04）

每个候选：`field_path`（如 `statement.new_balance`、`transactions[3].amount`）、`raw_value`、`normalized_value`、`raw_location{page,bbox,line}`、`parser_version`、`confidence`、`validations[]`、`confirmed_value`。

置信度合成（不只用模型自报）：
- 规则校验：金额格式、日期合法、币种合法、末四位 4 位。
- 交叉校验：明细和 = 合计；新余额 = 上期 − 还款 − 贷记 + 消费 + 费用 + 利息（容差 0）；账单日/到期日与规则一致；期间内交易日期落在周期内。
- 来源权重：文本层 > OCR；银行模板命中 > 通用。
- 阈值：≥0.95 自动预填（仍需用户整体确认）；0.6–0.95 高亮需逐项确认；<0.6 空白要求录入。

## 4. 校验与入账门槛（R-IMP-05）

关键冲突（任一）阻止入账：合计不符、币种不符、末四位无法映射到现有信用账户、账期与规则冲突且用户未选择。用户必须显式选择"按导入值/按规则值/手工值"，选择记录在版本 `reason`。

## 5. 幂等与去重（R-IMP-06）

去重键 = sha256(规范化(`credit_account_id` | `txn_type` | `currency` | `amount_minor` | `posted_on` 或 `txn_at@precision` | `bank_reference`? | `merchant` 规范化 | `source_document_sha256`?))。规则：
- 有银行参考号：参考号 + 账户 + 币种 + 金额 唯一；同参考号不同金额→"部分退款/调整"候选。
- 无参考号：金额 + 日期 + 商户 + 类型 + 账户；同日同额同商户出现两次且来源同一文档→视为两笔真实交易（文档内序号参与键）；来源不同文档→"疑似重复"由用户裁定，默认不入账。
- 预授权→入账：`preauth` 与后续 `purchase` 金额相同且 7 天内→关联为状态变化，不计两笔负债。
- 同一账单 PDF/邮件/截图：按 `statement_date + currency_account` 命中既有账单→新版本，不新建账单。
- 批次重放：同一文档 + 同一决策再确认→返回原结果，不改变余额（F-49）。

## 6. 平台限制（R-IMP-07/08）

- iOS：无短信读取；IdentityLookup 扩展只处理未知发件人、不能联网、不能写共享容器（S04）。
- Android：`sms` flavor 仅在上架 Play 时需权限声明表（v1 自签侧载、不上架，ADR-015），用途 "SMS-based money management"；不读取/上传非金融短信（S05）。
- Gmail：gmail.readonly/metadata 为受限 scope，服务器存储需年度安全评估（S06/S28）；无 label 级 scope。v1 不默认接入；若用户选择，走 OAuth 独立里程碑并在隐私中心显示权限实际范围。
- 自动转发：需收信服务与真实域名；v1 不提供虚构地址；若用户自建，记录域名与隐私依赖。

## 7. 导入模板（后台 AP-04）

模板 = 银行 + 文档类型 + 版本 + 字段定位规则（锚点文本、正则、表格列映射）+ 样例文件指纹 + 测试用例。模板变更需通过样例回归。

## 8. 测试要求

F-47 恶意样本；F-48 合计不符停在 needs_review；F-49 重复导入幂等；F-50 同日同额多笔；F-51 预授权转入账；F-52 同一账单三来源一笔负债；F-53 加密 PDF 密码不落盘。
